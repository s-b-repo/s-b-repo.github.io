// what it is

One MoE layer, drained by GPU, CPU and SSD at once

Peregrine is a heterogeneous Mixture-of-Experts inference engine written from scratch in Rust. Its scheduler keeps a GPU lane, a CPU lane and an io_uring SSD-streaming lane all draining the same MoE layer simultaneously — so a model far larger than your VRAM still runs. The reference target is a 744-billion-parameter int4 model streamed directly from disk.

It ships two binaries: peregrine, a stdio serve protocol with benchmark and automaton harnesses, and peregrine-serve, a native OpenAI-compatible HTTP server with continuous batching and a two-tier priority queue. Roughly fifty environment knobs tune I/O, scheduling and caching, and the numeric core is deliberately near-dependency-free.

The whole engine is engineered for bit-identical output: hand-written SIMD int2/int4/int8 kernels are validated against scalar references, the parallel worker pool is bit-identical to the serial path, and a simpler two-lane streaming implementation is kept purely as a correctness oracle.

// capabilities

What it does

Every claim here maps to a crate in the workspace — the design favours provable correctness over shortcuts.

Concurrent heterogeneous lanes

GPU, CPU and an io_uring SSD lane drain the same MoE layer at the same time, instead of running in separate phases.

Streams huge models from disk

int4/int8 quantized weights streamed with O_DIRECT and a priority-weighted warm cache — run models larger than RAM or VRAM.

OpenAI-compatible server

peregrine-serve exposes /v1/chat/completions (SSE and non-streaming), /v1/models and /health, with bearer auth and per-request priorities.

CUDA acceleration

Optional fused-quant matmul, WMMA W4A16, SwiGLU and attention/RoPE kernels behind a cuda feature, with CUDA graph capture and replay.

Token-exact kernels

AVX2/AVX-VNNI integer dot-products checked against a scalar oracle; the parallel path is bit-identical to serial output.

Tunable, dependency-light

~50 environment knobs for I/O, scheduling and caching; the numeric core avoids heavy dependencies by design.
